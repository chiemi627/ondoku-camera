# おんどくカメラ

プリントをスマホのカメラで撮ると、印刷された文を抜き出し、日本語訳をつけて読み上げる Web アプリ。
英語版（公文の英語プリントの音読練習用）とスペイン語版がある。

| 版 | URL |
| --- | --- |
| 英語 | https://chiemi627.github.io/ondoku-camera/ |
| スペイン語 | https://chiemi627.github.io/ondoku-camera/es/ |

ホーム画面に追加すると、それぞれ別のアプリになる（英語版は青、スペイン語版は赤のアイコン）。
設定・きろく・訳の保存は版ごとに分かれている。

## つかいかた

1. 「プリントを撮る」でプリントを撮影する（撮影済みの写真からも選べる）
2. 英文が1行ずつ抜き出され、日本語訳がつく
3. 「練習」で聞き方を選び、「ぜんぶ読む」。英文をタップすると、その行だけをくりかえす
4. 読みまちがいがあれば「なおす」で文字を直したり、いらない行を消せる。
   英語を直して「なおす」を閉じると、その行の訳がつけ直される。
   日本語も手で直していた場合は、そちらを尊重して触らない。
   直した内容は「きろく」にも書き戻されるので、翌日呼び出しても直したままになる

公文のプリントは「1回目／2回目」で聞き方を変える構成になっているので、練習の仕方を3つ用意した。

| 練習 | 動き |
| --- | --- |
| 英語を聞く | 英文だけを読む |
| 英語と日本語を聞く | 日本語訳と英文を続けて読む（既定は日本語→英語。設定で入れ替えられる） |
| まねして言う | 英文を読んだあと、口に出す時間をあける。長さは直前の英語の所要時間から決める |



はやさ（0.3〜1.2倍）、読み方、くりかえし回数（1〜3回）、英語の声を変えられる。

読み方は3つ:

| 読み方 | 動き |
| --- | --- |
| ふつう | 1文をひと息で読む |
| くぎって | 意味のかたまり（句読点か最大4語）ごとに区切り、間に0.5秒の間をおく |
| 1語ずつ | 1語ずつ読み、間に0.35秒の間をおく |

「くぎって」「1語ずつ」では、いま読んでいる語に色がつく。
端末によっては `rate` を下げても一定以下には遅くならない（iOS）ため、
区切って間をおく方式を併せて用意している。
設定と、読んだプリントの記録（直近10件）は端末の中に保存される。

## しくみ

- **文字の読み取り**：[Tesseract.js](https://github.com/naptha/tesseract.js) v7。端末の中だけで動く。サーバーには何も送らない
- **日本語訳の経路**：まとめ送り（改行区切り）→ 1文ずつ → 別の翻訳サービス（MyMemory）の順に手を変える。まとめ送りは URL に改行（`%0A`）が入り、これを弾く通信経路があるため、失敗しても1文ずつで試し直す。MyMemory は翻訳メモリの寄せ集めを返すことがあるので、機械翻訳の結果だけを取り出して使う
- **通信の自己診断**：設定の「翻訳の通信を調べる」で、3つの経路のどれが通ってどれが弾かれるかを端末自身が調べて表示する。端末やネットワークによって塞がれ方が違い、手元では再現できないため
- **日本語訳**：読み取るのは英語だけにして、訳は翻訳サービスで作る。プリント上の日本語を OCR で読む方式も試したが、実物での精度が実用に届かなかった。送るのは読み取った英文だけで、写真は送らない。一度訳した英文は端末に保存し、同じ英文は二度と送らない
- **行末のゴミを削る**：訳が横に並ぶ教材では、日本語がその言語の文字として誤読されて行末にくっつく（`¿Qué es esto? -hl:f1TI?`）。単語ごとの信頼度を見ると、本物の単語はおおむね 70 以上、くっついたゴミは 30 以下に分かれる。行末から、信頼度が低く単語として成り立たないものを削り、残った単語だけで行の信頼度を測り直す。行全体の平均で判断すると、ゴミに引きずられて正しい文ごと捨ててしまう（`¿Cómo se llama?` の単語は 85 なのに、行は 23 になっていた）
- **読み仮名の行を落とす**：単語の下に振られたカタカナの読みは、本文の半分以下の字の高さになる（実測で本文 84〜136、読み仮名 32〜45）。字が小さく、かつ語として通るものが少ない行は捨てる。小さい字でもちゃんとした文（指示文など）は残す
- **くっついた単語を切り分ける**：太字で字間が詰まると語の区切りが消える（`Esun`、`¿Cómosellama?`）。辞書に無い語を、よく使われる語の組み合わせに切り分けられるか試し、よく使われる語どうしの組み合わせを選ぶ。2文字以下の部品は本当によく使う語（順位1000以内）に限る。単語リストには断片（`fi`、`ga`）も入っていて、許すと `figa` → `fi ga` のように切ってしまうため（実測で、よく使う短い語は順位436以内、断片は3119以降）
- **会話の行頭のダッシュ**（`—Es un amuleto.`）を除く
- **誤読した日本語の除去**：プリント上の日本語は英語エンジンに無意味な英字列として読まれる。英単語として通る語が1つも無い行は英文ではないと判断して捨てる
- **読み上げ**：ブラウザの Web Speech API（端末内蔵の音声）
- **前処理**：撮影画像を長辺 1500〜2400px に調整し、グレースケール化とコントラスト伸張をかけてから認識させる
- **後処理**：信頼度の低い行、記号だらけの行、教材番号（`E 21a` など）を捨て、折り返された文をつなぎ、1行に複数の文があれば分ける
- **英文の掃除**：英語に現れない記号（`>` `|` `~` など罫線や注釈記号の誤認）を除去し、対になっていない引用符を落とし、分断された短縮形（`does n't` → `doesn't`）をつなぐ
- **語の照合**：[wordlist-english](https://www.npmjs.com/package/wordlist-english) の約38,000語と突き合わせる。辞書に無い語は、Tesseract が起こしやすい取り違え（`0`→`o`、`rn`→`m` など）を試し、**候補がちょうど1つのときだけ**自動で直す。直しきれない語は点線を引いて知らせる。大文字を含む語（人名・曜日・`TV` などの略語）は対象外

初回だけ OCR エンジンと英語の辞書データ（約4MB）を読み込む。
Service Worker がそれらを保存するので、2回目からはオフラインでも動く。

## 開発

静的ファイルだけ。ただし **push の前に必ず `python3 tools/build.py` を実行する**（下の「変更するとき」を参照）。

```bash
python3 -m http.server 8765
```

`http://127.0.0.1:8765/` を開く。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `app.js` | 処理本体。英語版とスペイン語版で共有する。言語による違いは冒頭の `LANGS` にだけ書く |
| `app.css` | 見た目。両版で共有 |
| `index.html` | 英語版の入口（画面の構成） |
| `es/index.html` | スペイン語版の入口。**`tools/build.py` が `index.html` から作る。直接は編集しない** |
| `sw.js` | オフライン用のキャッシュ（両版を一括で扱う） |
| `manifest.webmanifest`, `es/manifest.webmanifest` | ホーム画面に追加したときの設定 |
| アイコン類 | `tools/make-icons.py` が作る |

### 変更するとき

- **何を直しても、push の前に `python3 tools/build.py` を実行する。** `app.js`・`app.css` の中身から版の番号を作って読み込み先に `?v=番号` を付け、スペイン語版の入口を作り直す。GitHub Pages はファイルを10分間キャッシュさせる（`max-age=600`）ので、番号が変わらないと公開直後に古いファイルが使われる。動いている版は、設定の画面に「版 d2b3d9ab」のように出る
- 処理を直す → `app.js` だけ直せば両版に効く
- 画面の構成を直す → `index.html` だけ直す（スペイン語版の入口は `build.py` が作る）
- 言語で変わる文言は、HTML では `{L}`（言語名）・`{T}`（文の呼び方）と書いて `data-t` を付ける
- 新しい言語を足す → `LANGS` に1項目足し、`build-es.py` にならって入口を作る

### スペイン語版で英語版と違うところ

- **文字**：アクセント（á é í ó ú ü ñ）と ¿ ¡ を文字として扱う。英語向けの掃除のままだと記号ノイズとして消えてしまう
- **行の端の1文字**：a / e / o / u / y はそれだけで語になるので消さない
- **単語リスト**：[hermitdave/FrequencyWords](https://github.com/hermitdave/FrequencyWords)（MIT、OpenSubtitles の字幕から作られた頻度表）の上位5万語。npm にある既存の単語リストは 8MB あるうえ、`está` や `dónde` のような基本語が抜けていた
- **アクセントの復元**：OCR はアクセント記号を落としやすい（`tambien`）。辞書に無い語になったら、アクセントを付け直した形を試す。スペイン語では a↔o の入れ替えで別の実在語ができやすい（`nino` → `nina`）ので、アクセントの復元を先に試し、決まらないときだけ形の取り違えを試す
- **字幕由来の誤記の除去**：字幕の単語リストにはアクセントの書き間違い（`tambien`、位置違いの `tambíen`）も「語」として入っている。アクセント以外が同じ綴りの仲間のうち、最多の綴りの 1/12 未満しか使われないものは誤記とみなして辞書から外す。12 を境にしたのは実測から（直したい誤記は 14.5〜275 倍少なく、`esta`/`está`・`papa`/`papá` のように両方正しい語は 11.2 倍以内）
- **声**：同じ名前の声が地域違いで並ぶ（スペインとメキシコ）ので、地域を添えて表示する

## 音が出ないとき

iPhone の消音（マナー）モードは本体スピーカーだけを黙らせ、Bluetooth やイヤホンへの出力には効かない。
Web Speech API の読み上げはこの消音スイッチの影響を受けるため、
「イヤホンなら鳴るがスピーカーだと鳴らない」という症状になる。
消音スイッチ、着信音量、Bluetooth の接続が残っていないかを確認する。

Web からは端末が消音状態かどうかを知る手段がない（読み上げは無音のまま正常に完了する）ため、
アプリ側では画面に案内を出すだけにしている。

## 制限

- 手書きの文字はほとんど読めない。印刷された文字が対象
- 読み取りをまちがえることがある。そのための「なおす」モード
- 日本語訳をつけるときだけ通信する。機械翻訳なので誤りうる。おかしな訳は「なおす」で直せる
- 訳のつけ直しに失敗したときは前の訳を残し、「もう一度」で再試行できる（直した英語に古い訳が付いたままになるより、失われる方が困るため）
- 訳がつかなかった行があれば、件数と理由（`HTTP 429`、`Failed to fetch` など）を画面に出す。一部だけ失敗したときに黙って進むと、訳の抜けに気づけないため
- 翻訳側は文単位で区切るので、送った行数と返る訳の数が一致しないことがある。まとめ送りで取りこぼした行は1行ずつ送り直す。通信自体が失敗したときは同じ失敗を繰り返さない
- 訳に使っているのは Google の公開されていないエンドポイントで、予告なく止まる可能性がある。止まっても英語の読み上げには影響しない
